# GM3 コード実装

1. Issue、PR、依頼から目的、範囲、受け入れ条件を一文で整理する。曖昧さが結果を大きく変える場合だけ確認し、それ以外は既存実装から合理的に判断する。
2. `AGENTS.md`、同種のcontroller/model/component/API client、テスト、履歴を読み、APIから各フロントまで影響範囲を追う。一般論よりリポジトリの既存パターンを優先する。
3. 目的に必要な最小差分を実装する。無関係なrename、format、例外動作の変更、依存更新を混ぜない。認証・認可はフロントだけに任せない。
4. Docker環境は `AGENTS.md` の方針に従う。migrationは既存データとrollbackを考慮し、API変更は呼び出し元とOAS更新の必要性を確認する。UIはloading、empty、error、二重操作も扱う。
5. 変更に近い既存テスト、lint、型検査を実行する。必要なテスト追加が依頼範囲なら行い、別作業なら不足として報告する。
6. 変更内容、設計判断、実行した検証、未確認事項を日本語で報告する。commit、push、Issue・PR操作は明示された場合だけ行う。

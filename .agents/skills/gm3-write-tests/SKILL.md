# GM3 テストコード作成

1. Issue、差分、再現手順から守るべき機能の振る舞いを特定する。条件分岐、状態、権限、入力の組み合わせを整理し、変更に関係する意味のある分岐を洗い出す。
2. 近い既存テスト、fixture、helper、mockの使い方を読み、同じ層と書き方を選ぶ。新しいtest frameworkや大きな共通化を安易に追加しない。
3. 洗い出した各分岐について、期待どおり完了する正常系と、validation・認証認可・外部処理失敗・対象なしなどの異常系を作る。境界値と状態遷移も、振る舞いが変わる箇所を網羅する。組み合わせを機械的に総当たりせず、同じ結果になる重複ケースは増やさない。
4. 実装の内部構造ではなく、入力・操作と観測可能な結果を検証する。APIは `api/test` のRails testを使い、fixtureはテスト間の順序や固定件数へ依存させない。
5. userの画面フローは既存の `user/e2e`、adminは `admin_view/nuxt-project/e2e` のPlaywrightパターンに合わせる。mockはUI単体、実API・DB連携はreal flowとして目的を分ける。rentalには既存frameworkがなければ、テスト追加のためだけに導入せず相談する。
6. `AGENTS.md` のDocker方針に従い、まず対象ファイル、次に必要な関連範囲を実行する。追加テストが修正前に失敗し修正後に通ることを、可能なら履歴や一時差分で確かめる。
7. 分岐とテストケースの対応、正常系・異常系、実行結果、未検証範囲を日本語で報告する。production codeの修正は依頼に含まれる場合だけ行う。

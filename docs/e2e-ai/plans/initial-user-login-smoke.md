# E2E テスト計画: user ログインスモーク

## ステータス

- 状態: draft
- 作成日: 2026-06-30
- 対象: `user`
- 担当:

## 背景

参加団体向け Next.js 画面の入口であるログインが壊れると、申請や登録の主要導線へ進めなくなります。まずはログイン成功と最低限の遷移確認を E2E のスモークテストとして固定します。

## 対象範囲

- 画面: `user` のログイン画面とログイン直後画面
- 主要ルート: Playwright MCP 探索で確認する
- 関連 API: NextAuth 認証 API、Rails API のユーザー取得系
- 対象外: パスワード再設定、ユーザー作成、各申請フォームの詳細操作

## 前提

- 起動サービス: `api`, `user`
- 必要な Seed: ログイン可能な参加団体ユーザー。Seed 依存にするか、API で作成するかは探索後に決める
- 必要な環境変数:

```txt
PLAYWRIGHT_E2E_USER_EMAIL
PLAYWRIGHT_E2E_USER_PASSWORD
```

## 操作手順

1. ローカルの `user` ログイン画面を開く
2. メールアドレスとパスワードを入力する
3. ログインボタンを押す
4. ログイン後の画面へ遷移したことを確認する
5. ログイン後に参加団体ユーザー向けの主要 UI が表示されることを確認する

## 検証観点

- ログイン成功時にエラー表示が出ない
- ログイン後画面へ遷移する
- ログイン済みであることを示す表示、または主要メニューが表示される
- 認証情報が未設定の場合はテストを明確なメッセージで skip する

## テストデータ

- 作成するデータ: 未定
- 使う既存データ: `PLAYWRIGHT_E2E_USER_EMAIL` のユーザー
- 後始末: ログインのみならデータ削除なし

## Playwright MCP 探索メモ

- 探索 URL: `http://host.docker.internal:8003`
- 確認した要素: 未実施
- 安定して使えそうなセレクタ: 未実施
- 追加が必要そうな `data-testid`: 未実施

## 実装方針

- 追加 spec: `user/e2e/login-smoke.spec.ts`
- production code 変更: 原則なし。role/name で安定しない入力やボタンがあれば最小限の `data-testid` を検討する
- helper: 認証情報の環境変数チェック関数を spec 内に閉じる。複数テストで使い回す段階で `user/e2e/support/` へ切り出す

## リスク

- Seed ユーザーのメールアドレスやパスワードが環境ごとに揺れる
- ログイン後画面の表示文言が変更されると assertion が壊れる
- Next.js dev server と Rails API の起動タイミングで失敗する可能性がある

## レビュー観点

- [ ] 本番 URL にアクセスしない
- [ ] 秘密値を書いていない
- [ ] ログイン情報未設定時の挙動が明確
- [ ] ログイン後 assertion が画面仕様として妥当
- [ ] `make test-e2e` で実行できる
